# OpenWave 1.1.1

OpenWave 1.1.1 replaces the Python implementation with a native Rust runtime and expands device support, mixing, scenes and audio processing compared with v1.0.0.

## Patch corrections

- Isolated process-ownership tests from unrelated CI runner processes without weakening production ownership checks.
- Fixed RPM ownership lookup for missing files during interrupted uninstall and retry. Package-owned missing files remain protected.
- Added an explicit CI check using a disposable RPM database.
- Restored PipeWire 1.0 compatibility for meter, capture-keepalive and calibration PCM readers while preserving explicit capture targets.
- Made the device-free Ubuntu smoke session self-contained, with scoped Bubblewrap namespace permission, explicit accessibility dependencies, private tools and D-Bus services, and WirePlumber 0.4 policy-only configuration.

## Breaking changes

- The Python `wavexlr` package and Python module entry points are removed. Use `openwave` instead of `python3 -m wavexlr`, and `openwave-daemon` instead of `python3 -m wavexlr.daemon`.
- Source checkouts must be compiled before launching. Build all workspace binaries with `cargo build --locked --workspace --bins`, then run `target/debug/openwave`.
- Release packages now target x86-64 Linux instead of an architecture-independent Python installation. ARM is not included in this release target.
- GTK 4.14 or newer and libadwaita 1.5 or newer are required. Source builds require Rust 1.98.1 and the native development dependencies. Python is no longer an application runtime dependency.
- Custom service definitions, launch scripts and packaging that refer to Python modules or the old Python installation layout must be updated for the native executables.

## Device support and controls

The original device-support contributions below are carried forward into the Rust implementation.

- Added Wave:3 (`0fd9:0070`) support, originally contributed by **Lorenzo Lapucci** through [@AlexDicy's pull request #3](https://github.com/rikkichy/openwave/pull/3), including protocol mapping and monitor-mix controls.
- Added support for the XLR Dock `0fd9:00a6` variant, originally contributed by **Zedwil** in [afd31f3](https://github.com/rikkichy/openwave/commit/afd31f3c385532e4c31e27b34f768048bd68b621).
- Added support for multiple connected units, including units of the same model, with independent serialized control queues and hotplug handling.
- Added serialized 48 V phantom power control for supported XLR profiles, contributed by **Zedwil** in [754396b](https://github.com/rikkichy/openwave/commit/754396b2e2a45fcca2e92cd172412b64d33a372c). Scenes and calibration never change phantom power.
- Improved exact USB and ALSA pairing, hardware mute synchronization and recovery of temporarily unavailable ALSA controls.

## Mixing, scenes and audio processing

- Added custom mixes with creation, renaming, ordering and removal.
- Expanded source management with application bindings, hardware inputs and exclusive source groups.
- Added per-mix output selection, persistent master controls and published capture inputs for OBS and voice applications. Missing explicit outputs stay silent instead of switching to another device.
- Added scenes for source/send/master levels, mute, output choices and supported serial-matched hardware settings.
- Added low cut, gate, compression, EQ, delay and optional mono processing, plus cancellable raw-input calibration with explicit confirmation before applying a proposal.
- Added session-bus actions for controlling sources, mixes, scenes and effects from external tools.

## Reliability and integration

- Improved routing ownership, application-stream restoration, link repair and recovery after a PipeWire server restart.
- Hardened device targeting, rapid level/mute edits and silence-before-open group transitions.
- Preserved Python saved-volume loudness semantics and saved software mute during initial external-capture discovery.
- Added retryable shutdown and retained cleanup/restoration ownership instead of reporting completion while work remains pending.
- Added configurable white or black tray artwork with a red muted state, and improved tray-host loss and return handling.
- Added confirmed GUI and headless uninstall flows. Settings and scenes are preserved by default, while package-owned and unrelated files remain protected.
- Added explicit migration for older version-specific native launchers, including supported Nix profile wrappers.
- Updated native packaging, Nix integration and release checks. Native build targets include Ubuntu 24.04, Debian 13 and Fedora 43, with Arch and Nix packaging also provided.

## Upgrade notes and limitations

- Back up your OpenWave configuration before upgrading. Configuration remains under `${XDG_CONFIG_HOME:-~/.config}/openwave`; invalid stored data is preserved rather than silently replaced.
- Install the native package and update any custom Python-based launch or service commands. For manual removal, use `openwave --uninstall`; package-managed installations should follow their package manager's guidance.
- Health monitoring remains observation-only by default. Disruptive recovery requires the daemon's explicit `--auto-recover` option.
- Flatpak remains experimental and does not perform native host setup.
- The `0fd9:00c7` Dock variant remains disabled. Enabled profiles do not imply physical validation of every model, firmware or multi-device combination.
